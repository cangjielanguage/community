- url_parse和mdurl比较结果：

  两者定位相同（RFC 3986 URL 解析 + 百分号编解码工具库，均为 cjpm 工程、cjc 1.1.0、Apache-2.0 LICENSE），但 API 设计取向和功能范围差异很大：**mdurl 侧重“编码/解码的完整性”，url-parse 侧重“URL 对象模型的完整性与操作能力”**。

- cjuuid和cangjie-TPC/uuid4cj差异点：

  - **cjuuid**：单文件、零依赖、API 极简（`Uuid.v1/v3/v4/v5/v7` + parse/tryParse/比较/hash），支持 v7 与批量、多格式输出，适合快速集成；但无生成器抽象、v1 无时间单调性保障、无 MAC 读取、无测试、无 OHOS 目标配置。
  - **uuid4cj**：功能覆盖完整的 JUG v4.1.0——六类生成器（含 TIME_BASED_REORDERED 与 TIME_BASED_EPOCH）、Ethernet 地址读取、UUIDTimer 单调时钟、文件级时钟同步、UUID 类型分析/位级工具、比较器、公开摘要 API、加密安全随机，并配有全量测试与多平台（含 OHOS）构建；但 API 面大、上手成本高，且缺少 v7 的自定义时间戳注入与批量生成、多格式字符串输出。

- cjvalidator和cangjie-TPC/validator4cj差异点:

  - cjvalidator（0.1.0，static，Apache-2.0，无测试）：go-playground/validator 移植，193 个内置规则类（网络/UUID/编码/地理/颜色/文件/ISO/条件/跨字段），流式 ValidationBuilder + Translator i18n，跨字段与 required_if/with 条件联动内置。
  - validator4cj（0.0.1，dynamic，Apache-2.0，37 个测试）：Commons Validator 完整移植，ValidatorResources+XML+ValidatorAction 注册框架、Form/Field 模型、GenericValidator/GenericTypeValidator 类型化转换、CheckDigit 校验码体系（16 个实现）、五平台 target（含 OHOS + openssl/musl 链接）。
  **两者核心类同名（Validator）但 API 形态完全不同，不可直接替换。**
